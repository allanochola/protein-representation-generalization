## 8. Remote durability rule

A checkpoint is remotely durable only after all of the following:

1. version creation reports success;
2. asynchronous Kaggle publication reaches readable state;
3. dataset is independently reconfirmed PRIVATE;
4. expected files are remotely visible;
5. fresh downloaded bytes SHA-match local durable bytes.

A successful upload request alone is NOT sufficient.

## 9. Asynchronous publication rule

Kaggle Dataset version creation may complete asynchronously.

Therefore the publisher MUST NOT treat immediate post-upload download failure
as proof of corruption.

It must poll read-only dataset status/file visibility and verify fresh remote
bytes before declaring the checkpoint durable.

No second checkpoint version may be created merely because the preceding
version is still asynchronously publishing.
